## 1. 米国の指定と送信の記録

### 1-1. 送る前の確認

| 確認 | 実装 |
|---|---|
| 推論を米国に指定 | すべての呼び出しに `inference_geo: "us"`（`engines.ts`）。設定（`config.ts`）が `us` 以外なら送らない |
| ワークスペースの制限 | ① 運営者が確認した印 `TRANSLATION_WORKSPACE_GEO=us` がなければ、有料のエンジンを使わない（設定で止まる）。② 送る前に 1 時間ごとに preflight を行い、`inference_geo: "global"` の呼び出しがワークスペースに断られることを確かめる（Data residency：`allowed_inference_geos` にない地域はエラー）。送る文は固定の「ping」で、エラーは課金されない。通ってしまったら（＝米国以外も許されている）新しい翻訳を自動で止める |
| 運営者の確認 | `scripts/translate-eval/check-workspace.mjs`：global が断られること、us の応答に `usage.inference_geo = "us"` が返ること、（管理キーがあれば）Admin API の `data_residency` を表示 |

### 1-2. 実際の送信の記録

- **送る直前に、送信の記録を「送信中（sending）」で作る。** 作れなければ（許可の取り消し・版の違い・米国指定でない・停止中）送らない。
- **応答が来たら結果を書き足す**（`finish_translation_provision`）。記録そのものは消さない。

| 結果（outcome） | いつ | 翻訳結果 |
|---|---|---|
| `completed` | 応答があり、`usage.inference_geo = "us"` | 検証のうえ使う |
| `geo_mismatch` | 応答はあったが、地域が us でない、または書かれていない | **使わない・保存しない**。新しい翻訳を自動で止める（`halted_reason`）。運営者が原因を確かめるまで再開しない |
| `error_response` | API がエラーを返した（文章は届いている） | 使わない（原文を表示） |
| `unknown` | タイムアウト・接続断（届いたか分からない） | 使わない。**届いたものとして記録** |
| `sending` のまま | 処理の途中で関数が止まった | 「届いたか分からない」として扱う（記録は残る） |

- **やり直し**
  - SDK の自動のやり直しは止めた（`maxRetries: 0`）。
  - 接続エラー・429・529 のときだけ 1 回やり直す。1 回ごとに、予算の確保と送信の記録をしてから送る。
- **重複**
  - 同じ文・同じ言語は、翻訳中の目印（`claim`）で 1 人だけが送る。テストでは 3 人が同時に頼んでも記録は 1 件。
  - 目印は 2 分で期限切れになる。期限切れのあとに送り直した場合は、実際に 2 回送っているので記録も 2 件になる。
  - 翻訳済みを返すときは送らないので、記録しない。
- **二重の確認**：エンジンが何を返しても、応答の地域が `us` でなければ、サービス側でもう一度「地域の不一致」として扱う。

### 1-3. 記録する項目と保存期間（PPC のガイドラインとの照合）

検索で確認できた PPC の「第三者提供時の確認・記録義務編」の内容（**原文未確認**）：

| 規則の内容（検索結果による理解） | この設計 |
|---|---|
| 同意による提供の記録事項：本人の同意を得ている旨／第三者の氏名・名称など／本人を特定するに足りる事項／個人データの項目。提供年月日はオプトアウトによる提供の記録事項 | `consent_basis`（28 条 1 項の同意）と `consent_event_id`／`recipient`／`owner_id`／`source_type`・`source_path`。加えて日時・言語・指定と応答の地域・結果・request-id |

## 2. 年齢の確認

| 項目 | 内容 |
|---|---|
| サーバーで確かめる | ブラウザは生まれた年・月を送る。API（`route.ts`）と保存の処理（MemoryStore）と SQL（`grant_translation_consent`）の 3 か所で、**日本時間**で満年齢を計算し直す。誕生月は「月末生まれ」として少なめに数える。`ageConfirmed16: true` だけ送っても許可されない（テスト済み） |

| 回避の抑止 | 16 歳未満と入力したら、7 日間は再入力できない（`translation_age_gate`。残すのは「いつまで」だけで、期限後に消す） |
| 自己申告の限界 | 本当の年齢は確かめられない。年を偽れば許可できてしまう。規約の禁止事項に「生まれた年月を偽る行為」を加えた。ほかの手段（公的な身分証・決済情報など）は、取得する個人情報が増えるので採っていない |
| 保護者の同意への拡張 | ① `age_check` に `'guardian_consent'` を足す ② 保護者の同意の記録（保護者の連絡先・確認の方法・日時。本人とは別の表）を作る ③ 16 歳未満は `age_band = 'under_16'` とし、保護者の同意の記録があるときだけ許可する ④ 説明の版を上げて、保護者向けの説明を加える。どの方法で保護者を確かめるか（メール・書面など）は法務確認 |

## 3. 法定の記録・翻訳キャッシュ・費用の保存と削除

保存・削除の条件を 3 つに分け、それぞれ別の関数で消す。

| 区分 | テーブル | 期限 | 削除 |
|---|---|---|---|
| ② 送信の記録 | `translation_provision_log` | 送信日から 3 年（1 行ごとの `retain_until`） | `purge_translation_legal_records()` |
| ② 同意の記録 | `translation_consent_events` | 作成から 3 年。その同意に基づく送信の記録があれば、その記録の期限まで延長。いまも有効な許可の記録は消さない | 同上（期限切れ・参照なし・有効な許可ではないものだけ） |
| 説明の全文 | `translation_consent_notices` | 個人情報を含まないので消さない（同意の記録のハッシュを確かめるため） | ― |
| ① 翻訳キャッシュ | `content_translations` | 原文の編集・公開範囲の変更・選択の解除・取り消し・退会で消える（トリガー・関数） | 翻訳中・失敗のまま 1 日たった行を `purge_translation_cache()` |
| 年齢の再入力制限 | `translation_age_gate` | 7 日 | 同上 |
| ③ 回数制限 | `translation_daily`（ID あり） | 2 日 | `purge_translation_cost_records()` |
| ③ 確保の明細 | `translation_reservations`（ID なし） | 13 か月 | 同上 |
| ③ 月の合計 | `translation_budget`（ID なし） | 残す | ― |
| 退会の申請 | `account_deletion_requests` | 完了・却下から 3 年 | `purge_account_deletion_requests()` |

- 「最後の活動日から一律 3 年」をやめ、記録の種類と作り方ごとに期限を持たせた。前回の案は、同意の記録を作成日から 3 年で消すと、送信を続けている人のもとになった同意まで消えるという問題を直したものだった。
- SQL のテストで確認したこと：
  - 期限内は消さない。
  - 期限切れの変更・取り消しの履歴だけを消す。
  - 送信の裏づけになっている同意の記録と、いまの許可の記録は残す。
  - 退会後も期限まで残る。
  - 費用・キャッシュの削除は法定の記録に触れない。

## 5. 伏せ字・機微情報の処理

| 指示 | 対応 |
|---|---|
| AI が伏せ字を変えたときに誤って戻さない | 記号を `⟦1⟧` からランダムな `⟦a1b20⟧` に変えた。戻すのは、どの記号も「ちょうど 1 回」残り、知らない記号も、片方だけのかっこもないときだけ。それ以外は失敗にして原文を表示する（消えた・2 回・書きかえ・片方だけ・知らない記号はすべて失敗。語順の入れかえは戻す。テスト済み） |
| 住所・連絡先の誤検出 | 判定の前に全角・半角と横棒（− ー など）をそろえる。電話は数字だけ数えて 10〜11 桁（+81 は 11〜12 桁）に限る。架空の文で評価し、日付・時刻・点数・年・「東京都に住んでる」「3丁目の夕日」「LINE スタンプ」は送る |
| 健康・信条の語だけで止めすぎない | 3 段階に分けた。① 前科・障害者手帳・生活保護の受給・信仰団体への入信などは、それだけで送らない ② 病名・性的指向などは、「です」「と診断」などが続くか、私・母・〜さんなどが近くにあるときだけ ③ 病院・宗教・国籍・犯罪などは、本人や身近な人の話として書かれているときだけ。ドラマ・映画・ごっこ・本などの話題は送る |
| 個人情報を含む回答は安全側 | メール・電話・郵便番号・住所・LINE などの ID は、前回の「伏せ字にして送る」をやめ、**文ごと送らない**ことにした。伏せ字で送るのは URL と @ID だけ |
| ブロックの理由を UI で分かるように | 閲覧者：「一部の文は、連絡先や配慮が必要な内容を含む可能性があるため、翻訳していません」（分類は出さない。20 言語）。本人：同意画面の候補に「連絡先を含むため」「住所らしい内容を含むため」「配慮が必要な内容を含むため、翻訳されません」と表示する（日本語・英語） |
| 評価 | `scripts/translate-test/pii-cases.json`：架空の文 49 件（連絡先 11・住所 4・要配慮 9・送る 23・伏せ字 2）＋伏せ字を戻す 7 通り。**すべて期待どおり**。実在の情報は使っていない |

限界：言葉の一覧と形で判定するので、見落としも、取りすぎも残る。そのため、ポリシーと同意画面には「すべてを見つけられるとは限りません」と書いている。

## 7. 残る法務上の論点（追加分）

1. **送信の記録の義務の有無**：閲覧者の操作による送信が「本人に代わって提供」に当たるか。当たらないなら記録義務がある（いまは安全側で記録している）。
2. **記録の保存期間と起算点**：送信 1 回ごとの記録として 3 年でよいか。同意の記録を送信の記録の期限まで延ばす扱いでよいか（規則 21 条の原文で確認）。
3. **自己申告の年齢確認**：16 歳という線引きと、自己申告で足りるか。保護者の同意の方法。
4. **Anthropic の未成年者向けの要件**：16・17 歳の投稿を送ること、18 歳未満の閲覧者が AI の翻訳を見ることが、サポート記事の対象に当たるか。当たる場合に必要な措置。
5. **要配慮個人情報**：送らない判定は完全ではない。書かれてしまった要配慮個人情報が送られた場合の扱い（20 条 2 項の取得、28 条の同意の範囲）。
6. **退会の申請の記録**：完了後 3 年の保存で足りるか。本人確認の方法。
7. **規約 第 8 条第 5 項**：現行の広い人格権の不行使（第 2 項の利用）を狭めるか。
