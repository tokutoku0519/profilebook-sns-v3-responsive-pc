## 1. 法的な整理（個人情報保護法 27 条・28 条）

### 1-1. 前提

| 論点 | 整理 | 確度 |
|---|---|---|
| 運営者は「個人情報取扱事業者」か | 個人で運営していても、事業として個人情報データベース等を使っていれば対象になる（人数の下限はない） | 法務確認 |
| 送る文章は「個人データ」か | 回答はアカウントに結びついて DB に保存されている。そのため、名前や ID を付けずに本文だけを送っても、提供元（Miri）を基準に「個人データの提供」として扱うのが安全側 | 法務確認 |
| 「クラウド例外」（提供に当たらない扱い）が使えるか | 使えない見込み。PPC の Q&A は「クラウド事業者が個人データを取り扱わないこととなっている場合」を提供に当たらないとする。しかし Anthropic は文章を処理して翻訳を返すので、個人データを取り扱う | 検索抜粋（Q&A 原文未確認） |
| 委託（27 条 5 項 1 号）にすれば 28 条は不要か | **不要にならない。** 検索で確認した PPC の Q&A（Q12-1）の抜粋では、外国にある第三者へ取扱いを委託する場合も 28 条 1 項の同意などが原則必要とされている | 検索抜粋（Q&A 原文未確認） |

### 1-2. 根拠の選び方
28 条 1 項で外国にある第三者に提供するための道は 3 つある。

| 道 | Anthropic への送信に当てはめると | 判断 |
|---|---|---|
| ① 本人の同意（28 条 1 項）＋事前の情報提供（28 条 2 項、施行規則 17 条 2 項・3 項） | 書いた本人が「翻訳を許可する」をオンにする前に、決まった情報を見せて同意を得る | **この案の根拠** |
| ② 相手が基準適合体制を整えている（28 条 1 項、施行規則 16 条）＋継続的な措置と本人の求めに応じた情報提供（28 条 3 項） | Anthropic の DPA（データ処理補足契約）は GDPR 型の処理者契約。日本の個人情報保護法には触れていない（anthropic.com の原文で確認）。日本法の「相当措置」を契約で確保できているかの評価が必要で、個人運営で契約条件を交渉できないことを考えると不確実 | 採らない（法務の評価があれば併用を検討） |
| ③ 日本と同等の制度がある国（EU・英国） | 送信先は米国なので当たらない | 該当なし |

**この案の構成**
- 道 ① を根拠にする。
- ポリシーの文言は「委託または同意に基づき提供」のような曖昧な書き方をやめ、「**本人の同意に基づき、外国にある第三者に提供します**」と書く。
- 28 条 2 項の 3 項目（外国の名称／その国の制度／相手が講じる措置）は、同意画面とポリシーの両方で、同意の前に示す。

### 1-3. 道 ① に伴うほかの義務（法務確認が必要）

| 条文 | 内容 | この案での対応 |
|---|---|---|
| 29 条（第三者提供の記録） | 本人の同意に基づく提供は、記録の対象になると考えられる（27 条 5 項の委託などの例外に当たらないため） | 送信のたびに、日時・提供先・本人（書いた人の ID）・項目の種類を記録する設計を 7 章に入れた。記録の項目・保存期間（施行規則）は法務確認 |
| 23 条（安全管理措置）・ガイドライン通則編の「外的環境の把握」 | 外国で個人データを取り扱う場合、その国の制度を把握して措置を講じる必要がある | ポリシー「7. 安全管理措置」に送信先の国を記載する。Miri の他の処理拠点（Vercel・Supabase の地域）も合わせて確認する（10 章） |
| 32 条（保有個人データに関する事項の公表） | 安全管理措置の内容を本人が知り得る状態に置く | 同上 |
| 28 条 2 項の情報提供のあと、制度が変わった場合 | PPC の Q&A（Q12-13、検索抜粋）では、重要な変化があれば本人に情報提供することが望ましいとされる | 同意文言にバージョンを付け、変更時は再同意を求める（7 章） |

### 1-4.「外国の名称」を特定するための実装上の前提（**重要**）
- Anthropic の公式ドキュメント（Data residency）によると、推論を行う場所は既定で `inference_geo: "global"`（**どの国で動くか決まらない**）。
  - `"us"` を指定したときだけ米国内に限られる（料金は 1.1 倍）。
  - 保存先（Workspace geo）は現在 `"us"` だけ。
- 今の実装（`src/lib/translation/server/engines.ts`）は `inference_geo` を指定していない。そのため、このままでは同意画面で「アメリカ合衆国」と特定できない。
- **対応**
  - 有効化の前に、リクエストに `inference_geo: "us"` を付ける。
  - 翻訳専用のワークスペースで `allowed_inference_geos: ["us"]` に制限する。
  - これで外国の名称を「アメリカ合衆国」と特定できる。費用は 1.1 倍になる（月 $10 の上限は DB 側で守る）。
- 特定しない場合は、施行規則 17 条 3 項に従い、「特定できない旨とその理由」と「参考になる情報」を示す必要がある。この場合、同意の有効性について法務の評価が必要。
- サブプロセッサー（Anthropic の再委託先）の一覧と所在国は、trust.anthropic.com/subprocessors にある（DPA の Schedule 4）。作業環境から開けず**未確認**。再委託先の国を同意画面でどう扱うかは法務確認。

## 2. 外国の制度と Anthropic の保護措置

### 2-1. アメリカ合衆国の制度（28 条 2 項 2 号の情報）
個人情報保護委員会は、事業者が使えるよう、外国の制度に関する情報（各国・地域の情報提供文書）を公表している。ただし PPC の Q&A（Q5-8、検索抜粋）によると、制度の確認は提供元の責任で行い、委員会の情報は補助的な参照とされる。

同意画面とポリシーに載せる要約（**PPC の米国の情報提供文書の原文と照合してから確定すること**）：
> アメリカ合衆国には、日本の個人情報保護法のように民間事業者全般を対象とする包括的な連邦法はありません。分野ごとの連邦法（連邦取引委員会法、児童オンラインプライバシー保護法など）や、州ごとの法律（カリフォルニア州消費者プライバシー法など）によって、個人情報が保護されています。日本の制度との違いとして、本人の権利（開示・削除の請求など）や事業者の義務が、州や分野によって異なる場合があります。

リンク：個人情報保護委員会「外国における個人情報の保護に関する制度等の調査」（米国）【URL は PPC サイトで確認して記載】

### 2-2. Anthropic が講じている措置（28 条 2 項 3 号の情報）
anthropic.com の原文で確認できたもの：

| 措置 | 根拠 |
|---|---|
| 顧客が送った内容でモデルを学習しない（"Anthropic may not train models on Customer Content from Services."） | Commercial Terms of Service, Section B（2025-06-17 版） |
| 送られたデータは DPA に従って処理する（DPA は利用規約に組み込まれる） | Commercial Terms, Section C |
| Anthropic は処理者（processor）。顧客の文書による指示の範囲でのみ処理する | DPA B.1・B.2（2025-02-24 版） |
| 安全管理：保存時は AES-256 以上、公衆網の通信は TLS 1.2 以上で暗号化 | DPA Schedule 2, E |
| 再委託先の一覧を公開し、追加の前に通知する（顧客は 15 日以内に異議を述べられる） | DPA C.1・C.3、Schedule 4 |

| 標準の商用データ保存ポリシー：API の入力・出力は 30 日以内に削除。例外として、ゼロデータ保持の契約、利用規約違反への対応、法令上の必要がある | privacy.claude.com（**原文未確認・検索抜粋**） |

## 3. 翻訳の対象とする公開範囲（調査結果）

### 3-1.「公開範囲が未設定」の実態（既存のコードと DB で確認）

| 対象 | 実態 | 明示的に公開を選んだと言えるか |
|---|---|---|
| 基本情報 19 項目 | 編集画面のチップは「公開」を初期表示する。本人が触らなければ `book.__visibility` にキーがない（＝未設定）。画面と `get_visible_book` は未設定を公開として表示する | 未設定は**言えない**。`'public'` が保存されている項目だけ言える |
| ひとこと質問・BEST3・今月の BEST3 | 公開範囲を選ぶ UI がない（常に公開表示） | **言えない** |
| ひとこと・自己紹介（catchphrase・message） | チップがない | **言えない** |
| お題への回答 | DB の初期値が `'public'`。投稿画面は「公開」を選んだ状態で始まる。**デイリーのお題の画面は選択なしで `'public'` を保存する** | 投稿画面で選び直した場合以外は**言えない**（区別する列もない） |

### 3-2. 方針（この案）
1. 翻訳の対象は「**本人が翻訳を許可し、かつ明示的に公開を選んだもの**」に限る。
2. 未設定・選択なしの公開は対象にしない。
3. 明示的な公開を記録する仕組みは今ない。翻訳を有効にする前に、次のどちらかの実装が必要になる（今回は実装していない。11 章の差分を参照）。
   - **案 A**：各項目・各セクション・各回答で「公開」を選んだことを記録する（チップを押した時点で `'public'` を保存する／回答に「公開を選んだ」記録を足す）。
   - **案 B**：同意画面で「いま公開されていて、翻訳の対象になる項目」の一覧を本人に見せ、項目ごとに選んでもらう。選んだ項目の場所を同意の記録と一緒に保存する。
   - 推奨は案 B。既存の画面の挙動を変えずにすみ、同意の対象も具体的になる。
4. SQL 案の `require_explicit_public` の初期値は `true` にする（今は `false`）。

## 4. プライバシーポリシー 改訂案（該当条文の全文）

> 表記：Miri は個人運営のため、「当社」をすべて「運営者」に改める（4-0）。下の条文は改訂後の全文。
> 【 】は運営者が記入する箇所、または法務確認後に確定する箇所。

### 4-0. 前文（全面改訂）
> Miri（みんなのプロフィール帳SNS）の運営者である【運営者の氏名または屋号】（以下「運営者」といいます）は、運営者が提供するサービス「Miri」（以下「本サービス」といいます）の利用者（以下「ユーザー」といいます）の個人情報を、個人情報の保護に関する法律（以下「個人情報保護法」といいます）その他の関係法令およびガイドラインを守り、このプライバシーポリシー（以下「本ポリシー」といいます）に従って取り扱います。

### 4-1.「2. 取得する情報」（項目を追加）
> 運営者は、次の情報を取得します。
> 1. 登録情報：メールアドレス、パスワード（暗号化して保存）、ニックネーム、誕生日、その他ユーザーがプロフィール帳に登録した情報
> 2. 投稿情報：お題・PR質問への回答、日記、コメント、画像その他ユーザーが投稿したコンテンツ
> 3. 利用情報：本サービスの利用履歴（回答履歴、ポイント履歴、閲覧・操作ログ等）
> 4. 端末・接続情報：端末の種類、OS、ブラウザの種類、IPアドレス、Cookieその他の識別子
> 5. **翻訳機能に関する情報：翻訳の許可・取り消しの記録（日時、同意した説明文の版）、翻訳の実行記録（日時、翻訳した文章の種類と場所、翻訳先の言語）、翻訳結果**

### 4-2.「3. 利用目的」（1 項目を追加）
> 運営者は、取得した情報を次の目的で利用します。
> （既存の各号はそのまま）
> - **ユーザーが許可した場合に、そのユーザーが明示的に公開した回答を、他の言語で閲覧するユーザーのために翻訳して表示すること（翻訳結果の保存と再利用を含みます）**

### 4-3.「4. 第三者提供」（第 1 項を改訂）
> 1. 運営者は、次の場合を除き、あらかじめ本人の同意を得ることなく、個人データを第三者に提供しません。①法令に基づく場合、②人の生命・身体・財産の保護のために必要で、本人の同意を得ることが困難な場合、③その他個人情報保護法が認める場合。
> 2. **外国にある第三者への提供については「6の2. 翻訳機能と外国にある第三者への提供」に定めるとおりとし、本人の同意を得た場合に限り行います。**
> （PR 質問・統計情報に関する既存の各項はそのまま）

### 4-4.「6. 委託」（改訂）
> 運営者は、利用目的の達成に必要な範囲で、個人データの取扱いの全部または一部を、クラウドサービス・データベースサービスの提供事業者などの第三者に委託することがあります。この場合、運営者は、委託先を適切に選び、必要かつ適切な監督を行います。**翻訳機能のための外国の事業者への送信は、委託としてではなく、「6の2」に定める本人の同意に基づく外国にある第三者への提供として行います。**

### 4-5.「6の2. 翻訳機能と外国にある第三者への提供」（新設）
> 1. **翻訳機能の内容**
>    本サービスには、他の言語で閲覧するユーザーが、ほかのユーザーの回答を機械翻訳で読める機能（以下「翻訳機能」といいます）があります。
> 2. **本人の同意**
>    翻訳機能で回答が翻訳されるのは、その回答を書いたユーザーが、本項に定める情報を確認したうえで、本サービスの設定から「翻訳を許可する」を選んだ場合に限ります。初期設定は「許可しない」です。許可しない場合、ユーザーの回答が翻訳のために外部に送信されることはありません。
> 3. **翻訳の対象**
>    - 対象は、プロフィール帳の自由記入の回答（ひとこと、自己紹介、好きなもの・嫌いなもの、BEST3、ひとこと質問への回答など）と、お題への回答のうち、ユーザーが公開を選び、かつ翻訳を許可したものです。
>    - 氏名、ニックネーム、ユーザーID、メールアドレス、誕生日、公開範囲を「フォロワー限定」「非公開」にした内容、日記、ブログ、コメントは対象にしません。
> 4. **送信先**
>    翻訳のため、次の事業者に情報を送信します（以下、この事業者を「翻訳事業者」といいます）。
>    - 事業者：Anthropic, PBC（翻訳には同社のAIモデルを使います）
>    - 所在する外国の名称：アメリカ合衆国（翻訳の処理と保存は、アメリカ合衆国内の設備で行うよう設定しています）
> 5. **送信する情報**
>    - 翻訳する回答の本文、その回答の質問文、翻訳先の言語、固有名詞の扱いなどに関する翻訳の指示を送信します。
>    - 氏名、ユーザーID、メールアドレスなどの登録情報や、閲覧したユーザーの情報は付け加えません。
>    - ただし、回答の本文や質問文に、ユーザー本人やほかの人を特定できる内容が書かれている場合は、その内容も送信されます。
> 6. **送信するとき**
>    他の言語で閲覧するユーザーが「翻訳を見る」を選んだときに送信します。同じ文章を同じ言語に翻訳した結果が保存されている場合は送信しません。翻訳に失敗したときは、改めて送信することがあります。
> 7. **アメリカ合衆国の個人情報保護制度**
>    アメリカ合衆国には、日本の個人情報保護法のように民間事業者全般を対象とする包括的な連邦法はなく、分野ごとの連邦法や州法によって個人情報が保護されています。そのため、本人の権利や事業者の義務が、日本の制度と異なる場合があります。詳しくは、個人情報保護委員会が公表している情報【URL】をご覧ください。
> 8. **翻訳事業者が講じている措置**
>    翻訳事業者は、運営者との契約（利用規約とデータ処理補足契約）において、次の措置をとることを定めています。
>    - 送信された情報を、運営者の指示の範囲でのみ処理すること
>    - 送信された情報をAIモデルの学習に利用しないこと
>    - 保存時と通信時に暗号化を行うこと
>    - 再委託先を公表し、追加する前に通知すること
>    - 本人からの請求への対応に協力すること
> 9. **翻訳事業者での保存**
>    - 翻訳事業者が公表している方針では、送信された文章と翻訳結果は、保存されないか、保存される場合でも原則として30日以内に削除されます。
>    - ただし、法令上必要な場合や、翻訳事業者の安全性確認の仕組みで利用ルールに反するおそれがあると判定された場合には、最長2年間保存されることがあります。
>    - 翻訳事業者での保存と削除は翻訳事業者の方針に従い、運営者が個別に削除を指示することはできません。
> 10. **運営者での保存**

## 10. 法律の専門家に確認していただきたい論点

1. **28 条の根拠**：本人の同意（道 ①）を根拠にすることの妥当性。同意画面（6-2）の内容が、28 条 2 項と施行規則 17 条 2 項の情報提供を満たすか。チェックボックスとボタンによる同意取得の方法が適切か。
2. **クラウド例外・委託との関係**：Anthropic への送信が「提供」に当たるか（クラウド例外を使えないという整理でよいか）。同意に基づく提供とした場合、27 条（委託）と 25 条（委託先の監督）が適用されないという整理でよいか。
3. **基準適合体制（道 ②）の評価**：Anthropic の DPA（GDPR 型・SCC）で、施行規則 16 条の「相当措置」を契約で確保していると言えるか。言えるなら併用するか。
4. **外国の名称の特定**：`inference_geo: "us"` を設定すれば「アメリカ合衆国」と特定できるか。サブプロセッサーの所在国をどう示すか（未確認）。
5. **29 条の記録**：同意に基づく提供の記録として何を記録すべきか（7 章の設計で足りるか）。保存期間をどうするか。退会後も保存することと「退会で消去」の記載をどう両立させるか。
6. **外国の制度の説明**：2-1 の要約は PPC の情報提供文書と整合するか。リンク先を確定すること。
7. **Anthropic の保存期間の表現**：公式ドキュメント（既定では保存しない）とプライバシーセンター（30 日以内に削除）の違いを踏まえた 4-5 第 9 項の文言が適切か。最長 2 年の例外の書き方。
8. **同意の撤回**：撤回後に Anthropic 側のデータを削除できないことを、文言（4-5 第 11 項）で十分に説明できているか。
9. **明示的な公開の判断**：3 章のとおり、未設定・選択なしの公開を対象外にする方針でよいか。案 A と案 B のどちらを採るか。
10. **未成年者**：翻訳の許可に法定代理人の同意が必要な年齢（PPC の Q&A は 12〜15 歳以下が目安、二次資料のみ）。二次資料では 16 歳未満に関する法改正の動きも報じられており、施行時期と内容を確認すること。年齢をどう確認するか。Anthropic の Usage Policy は、未成年者が使う場合に追加のガイドラインの遵守を求めている（サポート記事は未確認）。
11. **第三者の個人情報**：回答に書かれたほかの人の情報を、書いた本人の同意だけで外国に送ってよいか。注意喚起（4-10）だけで足りるか。要配慮個人情報（病歴など）が書かれる可能性への対応。
12. **国外の利用者**：20 言語で提供しているため、各国の法律が適用される可能性がある。主なものは、EU・英国の GDPR（域外適用）、韓国の個人情報保護法（国外移転の同意）、中国の個人情報保護法（越境移転の個別同意など）、タイの PDPA、米国の COPPA（13 歳未満）・州法。対象とする国の範囲と、対応するかどうか。
13. **個人運営の表示**：氏名・住所の公表範囲（特定商取引法の表示との整合を含む）。

## 11. 実装と条文の照合結果（2026-11-06 時点のコード）

| 条文に書いた動作 | 実装 | 結果 |
|---|---|---|
| 許可は初期値オフ。オフなら送信しない | `translation_consents` がない、または allow=false なら原文を取り出さない（SQL `translatable_source`・MemoryStore） | **一致**（SQL・API のテストで確認済み） |
| 許可を取り消したら、以後送信しない・翻訳結果を削除 | `set_translation_consent(false)` でその人の翻訳をすべて削除。以後は取り出さない | **一致** |
| 公開範囲を変えたら翻訳結果を削除 | プロフ帳：`__visibility` が変わると、その人のプロフ帳の翻訳をすべて削除。回答：公開範囲が変わると、その回答の翻訳を削除 | **一致** |
| 回答を編集・削除したら翻訳結果を削除 | プロフ帳：原文の md5 が変わった項目を削除。回答：本文の変更・削除で削除 | **一致** |
| アカウントを削除したら翻訳結果を削除 | `profiles` の削除で、外部キーにより翻訳と許可が消える | **一致**（ただし下の差分 ①・②） |
| フォロワー限定・非公開・日記・ブログ・コメントは対象外 | 原文は「ログインしていない人」として読む。項目は許可リストだけ | **一致** |
| 登録情報・閲覧者の情報を付けない | エンジンに渡すのは本文・質問文・言語・用語集の指示だけ。翻訳のコードに文章のログ出力はない | **一致** |
| 同じ文章・同じ言語は送信しない。失敗時は再送がありうる | キャッシュ。失敗・中断は 2 分後に取り直せる | **一致** |
| AI による翻訳であることを表示 | 「AIによる翻訳です…」を表示（仮の翻訳のときは「テスト用の仮翻訳です」） | **一致**（AUP の表示義務にも対応） |
| Anthropic での処理・保存は米国内 | `inference_geo` を指定していない（既定は global） | **差分 ③** |
| 明示的に公開したものだけ | 本人の許可があれば、未設定も公開として扱う。回答の `'public'` が明示の選択かを区別できない（デイリーのお題は選択なしで `'public'`） | **差分 ④** |
| 同意画面に 28 条 2 項の情報を表示し、確認してからオン | マイページのカードはスイッチを直接オンにできる。国・制度・措置・保存期間の表示がない | **差分 ⑤** |
| 許可・取り消し・送信の記録を保存 | `translation_consents` は現在の状態と更新日時だけ。版・履歴・送信記録がない | **差分 ⑥** |
| 【○歳】未満は法定代理人の同意 | 年齢の確認なし | **差分 ⑦** |

### 差分の一覧（次の実装で対応。今回は文面と調査だけのため未修正）
1. **アカウントの削除の手段がない**：アプリに退会機能がなく、運営者が Supabase で削除する前提になっている。ポリシーの「アカウントが削除されたとき」は、運営者による削除（請求を受けて行う）を指すと明記するか、退会機能を作る。
2. **費用の記録に ID が残る**：`translation_reservations`・`translation_daily` は、退会後も依頼者・持ち主の ID を残す（外部キーなし）。退会時に ID を消して匿名化するか、保存の目的と期間をポリシーに書く。
3. **送信先の国を米国に固定する**：`engines.ts` のリクエストに `inference_geo: "us"` を付ける。翻訳専用のワークスペースは `allowed_inference_geos: ["us"]` にする。費用の見込みを 1.1 倍に更新する（`config.ts` の料金）。
4. **明示的な公開だけにする**：SQL の `require_explicit_public` の初期値を `true` に、`shared.ts` の判定もそろえる。案 A または案 B で、明示の選択を記録する仕組みを作る。それまでは、回答・ひとこと質問・BEST3 は翻訳されない。
5. **同意画面**：6 章の確認画面を作る。マイページのスイッチは確認画面を経由させる。外国の制度のリンクを確定させる。
6. **同意と送信の記録**：7 章のテーブルと関数を SQL 案に追加し、API から記録する。説明文の版が変わったら再同意を求め、それまで新しい送信を止める。
7. **未成年者**：年齢の扱いを決めてから、確認画面に年齢の確認（自己申告または保護者の同意の確認）を加える。

> 有効化（`TRANSLATION_ENABLED=true` と有料 API）の前提条件は、差分 ③〜⑥ の対応と、10 章の法務確認。本番は今も翻訳が止まっているので、差分による実害は今のところない。
